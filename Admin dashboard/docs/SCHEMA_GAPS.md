# SCHEMA_GAPS — فجوات قاعدة البيانات الموثّقة (عقد متجمد)

تم الالتزام الصارم بعدم اختراع أي جدول أو عمود أو RPC أو Storage bucket خارج العقد المتفق عليه. فيما يلي العمليات غير المدعومة حاليًا على مستوى المخطط (Schema) وطريقة التعامل معها في الواجهة:

1. **لا يوجد جدول وحدات دراسية (`units`)**: الدروس ترتبط مباشرة بـ `(course_id, term_id)`. لا توجد شاشات أو خيارات لوحدات دراسية.
2. **لا يوجد رفع ملفات PDF**: لا يوجد bucket لمستندات الدروس؛ المستندات تُضاف كروابط HTTPS فقط معتمدة في `allowed_link_domains` (مثل Google Drive)، والصور فقط تُرفع في `content-media` بحد أقصى 5 ميجابايت.
3. **لا يوجد `payment_method` في `payment_requests`**: الواجهة لا تعرض حقل وسيلة دفع ولا تفترض قيمة له؛ تُعرض فقط بيانات التحويل الموجودة (`sender_phone`, `amount_egp`, `proof_path`).
4. **لا يوجد جدول إعدادات عامة (`settings`)**: مدة الفترة التجريبية (30 يومًا) ثابتة برمجيًا في قاعدة البيانات؛ صفحة الإعدادات تعرض توضيحًا للقراءة فقط بدلًا من حقل تعديل وهمي.
5. **لا يوجد إلغاء اشتراك إداري (`admin_cancel_subscription`) أو حذف/تعديل هاتف/تصفير كلمة مرور الطالب أو `bulk_import_students`**: لم يتم إضافة أزرار وهمية لهذه العمليات في الواجهة.
6. **تعديل `price_egp` أو `is_active` في `plans`**: يتم عبر `UPDATE` مباشر على `plans` مع ملاحظة تأكيد بأن التعديل لا يغيّر الاشتراكات أو الطلبات السابقة.
7. **تكرار درس أو امتحان (`Duplicate`)**: نظرًا لعدم وجود دالة RPC ذرية لنسخ الدرس بعناصره وأسئلته أو الامتحان بأسئلته وخياراته، تم توثيق الحاجة لدالة RPC ذرية مستقبلية وعدم تعريض نسخ جزئي قد يفشل في منتصف العملية.
8. **إعادة ترتيب Bulk Reorder via RPC**: يعتمد حاليًا على `upsert` جماعي بـ `onConflict: 'id'` يشمل جميع الأعمدة `NOT NULL` المطلوبة.
9. **التقارير المجمّعة (`Reports`)**: لعدم وجود RPCs تجميعية على الخادم، تجلب الواجهة حتى 20,000 صف وتُجري التجميع على المتصفح مع إظهار شريط تنبيه واضح عند الاقتطاع.
10. **إنشاء حسابات الموظفين (`create-staff`)**: يتطلب Edge Function مخصصة (`create-staff`) بصلاحية `service_role` لأن المتصفح لا يملك إنشاء مستخدمين في `auth.users`. عند غيابها تظهر رسالة واضحة للمستخدم (راجع `docs/edge-create-staff.md`).
